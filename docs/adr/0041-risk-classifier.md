# ADR-0041: Rule-based risk classifier for proposed commands

Date: 2026-10-26
Status: accepted

## Context

Architecture §8 puts every command an AI provider proposes into one of four tiers: read-only (runs automatically), low-impact change (approval, or automatic per server group), high-impact change (approval always) and forbidden (blocked). Classification uses rules only, allow-lists and deny patterns, with unknown commands defaulting to high impact; the AI's opinion is never an input. Proposals are free-form shell command lines written by a model that may be steered by prompt injection (§8, "Threats addressed"), so the classifier must assume an adversary crafts the text to look harmless.

Questions: how much of the shell to understand, which commands the built-in rules know, what administrators can configure and at which scope, how a decision is reported, and where the per-group automation flag lives. There are no server groups yet.

## Decision

**Module.** `crates/server/src/remediation/risk.rs`: `classify(command, &RuleSet) -> Decision`, a pure function. A `Decision` is `{tier, rule, reason}`, where `rule` is `{"source": "builtin", "id": "readonly.df"}` or `{"source": "configured", "id": <uuid>}` and `reason` is one sentence for the approval queue and the audit log. Built-in rule IDs are stable strings (`syntax.*`, `readonly.*`, `low.*`, `high.*`, `forbidden.*`, `default.unknown`).

**Conservative parsing.** A small lexer splits the command as a POSIX shell would split a simple command or a pipeline: single and double quotes and backslashes are resolved, so `'r'm` is `rm`. It refuses, as high impact with a named rule, everything else: `;`, `&`, `&&`, `||` and interior newlines (`syntax.command_list`); `$` and backticks anywhere outside single quotes, even `$HOME` (`syntax.substitution`); `<`, `>`, here-documents and here-strings, `2>&1` included (`syntax.redirection`); `(`, `)`, `{`, `}` (`syntax.grouping`, which also covers brace expansion); `#` at a word start, `!`, `~` at a word start; unterminated quotes and line continuations; `|&`. Before lexing, non-ASCII characters (lookalikes such as Cyrillic `ԁ`, zero-width and bidirectional marks, full-width letters) and control characters are high impact; surrounding whitespace and newlines are trimmed. A stage starting with `NAME=value` is high (`syntax.env_prefix`). Unquoted `*`, `?`, `[` are high (`syntax.glob`) except in the file operands of the log and `/proc` readers, which are checked so no expansion leaves them. A program given as a path resolves to its base name only in the standard directories (`/bin`, `/sbin`, `/usr/bin`, `/usr/sbin`, `/usr/local/bin`, `/usr/local/sbin`), so `/bin/df` is `df` but `/tmp/df` is unknown. Commands over 4096 bytes are high.

**Pipes.** Allowed only into built-in read-only filters reading the pipe, each with an option allow-list and no file operands: `grep` (no `-r`, `-f`), `head`, `tail` (no `-f`), `sort` (no `-o`, `--compress-program`), `uniq` (no output file), `wc`, `cut`, `tr`. Any other stage is high (`syntax.pipe_target`). The pipeline takes the tier of its first stage.

**Built-in rules.** Read-only, each with the options it accepts (others make the command unknown): `df`, `free`, `uptime`, `uname`, `whoami`, `nproc`, `hostname` (no argument or a reporting flag), `id`, `date` (no `-s`), `ps`, `netstat`, `lscpu`, `who`, `w`, `ss` (no `-K`, `-D`, `-E`), `top` (batch, one iteration), `vmstat` (bounded), `lsblk`, `ip <object> [show|list]`, `dmesg` (no `-c`, `-C`, `-w`), `ls` of absolute paths, `systemctl status|show|cat|is-*|list-*`, `journalctl` with read-only options and `FIELD=value` matches (no `-f`, `--vacuum-*`, `--rotate`, `--flush`, `-D`, `--file`), and `cat`, `head`, `tail`, `grep` of files under `/var/log/` or `/proc/` without `.` or `..` components, without the `/proc` entries that expose secrets or lead elsewhere (`environ`, `mem`, `kcore`, `root`, `cwd`, `exe`, `fd`, `map_files`, …), and without globs under `/proc` or globs that could match `..`. Low impact: `systemctl start|restart|reload|try-restart|reload-or-restart <unit>…` except units that cut off the host or MonitorFlow (`ssh`, `sshd`, `dbus`, networking, `systemd-*`, `getty*`, `monitorflow-*`, and `.target`, `.mount`, `.slice`, … units), which are high; `apt[-get] clean|autoclean` and `dnf|yum clean …`; and `find <dir> -mindepth 1 [-xdev] -delete` for a configured cache directory (`rm -rf <dir>/*` is a glob on a write command, so high). High impact, by category: privilege changes (`sudo`, `su`, `doas`, …), shells and interpreters (`sh`, `bash`, `python`, `perl`, `awk`, …), wrappers that run another command (`env`, `nohup`, `timeout`, `xargs`, `eval`, `source`, `exec`, `find`, `watch`, …), package managers, file and configuration changes (`rm`, `cp`, `mv`, `sed`, `tee`, `chmod`, `sysctl`, `mount`, …), `kill`/`pkill`/`killall`, `reboot`/`shutdown`/`init`, and every other `systemctl` verb. Everything else is `default.unknown`, high.

**Deny patterns.** Checked before anything else, so deny always wins, even over a command the strict lexer refuses: the command is cut leniently at every shell operator (and `$(`, backticks), quotes are resolved, words holding a command of their own (`bash -c '…'`, `"$(…)"`) are searched recursively, and program paths are matched both as written and by base name. Built-in deny rules: recursive `rm` of `/` or a top-level system directory (`forbidden.rm_root`, after resolving `.`, `..` and `/*`), `mkfs*`, `mke2fs`, `mkswap`, `wipefs`, `blkdiscard` (`forbidden.format`), `dd of=/dev/<disk>`, `shred /dev/<disk>` and redirections onto a disk (`forbidden.raw_disk_write`), and the classic fork bomb.

**Administrator rules.** Table `remediation_rules` (migration `20261026100000_remediation_rules`, add-only): per customer, optionally narrowed to one site. Sites stand for server groups until groups exist; a later group column can be added beside `site_id`. Kinds: `deny` (a word pattern that makes any command containing a match forbidden), `allow` (a word pattern matched against the whole command, with tier `read_only` or `low_impact`) and `cache_dir` (a directory for the low-impact cache rule; two components or more, outside system directories, not `/var/lib`, `/var/log`, …). Pattern words glob with `*` and `?` within a word and `**` across words, ASCII only, at most 512 bytes; matching is dynamic programming, so patterns cannot blow up. Allow rules only extend the built-ins: they apply to commands no built-in rule decided (unknown programs, or read-only programs with other arguments), after every syntax rule, so they cannot unlock shells, `sudo`, packages, `kill`, reboots, command lists or redirections; rules naming such programs are refused at creation. When several allow rules match, the most cautious tier wins. The rule set for a server is its customer's rules plus its site's.

**Automation flag.** Table `remediation_policies (customer_id, site_id, low_impact_auto)`: the site row overrides the customer row, and without either low-impact commands need approval. `store::low_impact_auto` is what the incident loop reads; this ADR only stores it.

**API.** `GET/POST /api/remediation/rules`, `DELETE /api/remediation/rules/{id}`, `GET/PUT /api/remediation/policies` and a dry run `POST /api/remediation/classify`, with the access rules of campaigns (ADR-0033): a role on the customer as a whole to read, an administrator role on it to change. Changes are audited as `remediation_rule.create`, `remediation_rule.delete` (with the deleted rule's pattern) and `remediation_policy.update`. There is no update of a rule: delete it and create another, so the audit log reads as a list of whole rules.

## Consequences

- The tier of a proposal is reproducible from the command text and the stored rules alone, and every decision names the rule that made it.
- The parser refuses far more than it understands. Harmless forms such as `2>/dev/null`, `$(date)` or `cmd1; cmd2` of two read-only commands are high impact; the AI prompt (ADR-0039) should ask for one command per proposal, without redirections.
- Deny matching is deliberately loose: a quoted grep pattern such as `grep 'rm -rf /' /var/log/syslog` is forbidden. False positives block a proposal, never let one through.
- Read-only file rules trust the paths under `/var/log` not to be symlinks to secrets; the agent's command user should not be able to read what it should not send (ADR-0040 redacts outputs as a second layer).
- `ps`, `ss` and `journalctl` outputs can contain secrets from command lines and logs; they are read-only but still go through redaction before reaching the AI.
- The incident loop (later) calls `rule_set_for_server` and `classify` for each proposal, then `low_impact_auto` for low-impact ones. Allow and deny rules for server groups other than sites need a migration adding the group column.
